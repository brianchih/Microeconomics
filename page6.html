第 1 課：別被數學符號嚇到！整個演算法其實只有 7 個積木

第 2 課：兩大核心引擎——「人找缺（Loop 2）」與「缺找人（Loop 3）」

附錄 A 最精妙的設計，在於把所有配對動盪拆成兩個互相呼叫的 while 迴圈：Loop 2 與 Loop 3。

// 總指揮 Loop 1：每次放一位新人進場，直到兩個堆疊都清空 while (還有未進場的新申請人) { 把下一位申請人放進 Applicant_Stack; while (Applicant_Stack 不為空 OR Program_Stack 不為空) { Loop_2(); // 第一引擎：處理「被踢掉的人」去找新工作 Loop_3(); // 第二引擎：處理「突然空出來的職缺」去招回好人才 } }

為什麼需要兩個引擎？（大學生搶社團幹部比喻）

  • 引擎一：Loop 2（人找缺 / Applicant Stack）
    當某位同學被踢出社團（或因為情侶另一半落選而被迫連帶退出），他就會被推進 Applicant_Stack。Loop 2 會拿出他的志願表，幫他往下一順位的社團投遞。如果新社團收了他、但把另一位較弱的社員踢出來，那位新被踢的人也會被丟進 Applicant_Stack，直到所有「無家可歸的人」都找到歸宿（或志願表全部投完）為止！
  • 引擎二：Loop 3（缺找人 / Program Stack）
    為什麼會「突然多出空缺」？因為情侶檔或附帶先修志願者一旦有一邊沒上，就必須主動放棄原本已經佔住的另一邊名額！這個突然空出來的社團名額會被丟進 Program_Stack。
    Loop 3 會打開這個社團的錄取名單，從第一名往下問：「你現在去的地方，是不是比我們社團還差？」只要找到有人點頭說「對！我本來超想去你們社團，只是當初沒擠進去」，Loop 3 就會把這個人放回 Applicant_Stack 讓他重新申請跳槽過來！
💡 關鍵細節：情侶檔在 Place_Applicant 裡的「雙重安檢」
在附錄 A 的 Place_Applicant 函式中，如果來申請的是一對情侶（例如大偉與小美），程式必須同時檢查兩家醫院是否都願意收他們（Both programs accept）：
• 只要其中任何一家醫院拒絕，這對情侶就兩邊都不能進去，必須直接看下一組「成對志願」！
• 只有兩家醫院同時點頭，程式才會正式錄取兩人，並把兩家醫院原本排名最後的倒楣鬼踢進 Applicant_Stack。

當所有單身學生與情侶檔都透過 Loop 1～3 安頓好之後，附錄 A 還有最後兩道關卡（頁 57–59）：Adjust_Quotas（名額流用）與 Check_Even_Odd（偶數名額限制）。

收尾關卡 1 · Adjust_Quotas（名額流用調整）

為什麼不能在配對中途就決定要不要「流用名額」？

假設「資工系轉學考」規定：若大二名額沒招滿，剩餘缺額自動流用給大三名額。在配對還沒全部跑完之前，大二隨時可能有人進來或離開，因此必須等全場第一次穩定後，再執行 Adjust_Quotas：

  1. 檢查所有設定「流用規則」的單位，發現大二真的有 2 個空缺沒招滿。
  2. 正式把大二的上限減 2，並把大三的上限加 2（大三突然多了 2 個空缺！）。
  3. 把大三放進 Program_Stack，重新喚醒 Loop 2 和 Loop 3，讓原本被大三拒絕的高分學生遞補進來！
收尾關卡 2 · Check_Even_Odd（偶數名額限制）

如果規定「必須偶數人」的單位只招到 3 個人怎麼辦？

假設某醫院要求偶數名額（希望 4 人，但目前只招到 3 人）：

  1. Check_Even_Odd 偵測到目前錄取人數為 3（奇數）。
  2. 程式無情地把這 3 人當中排名最末位（第 3 名）的申請人踢出去（讓該醫院暫時變成 2 人），並把這位被踢的人放進 Applicant_Stack 去找其他醫院！
  3. 萬一在後續遞補中，這家醫院又意外補進第 3 人變回奇數，Check_Even_Odd 會再次巡邏檢查，直到所有單位都符合規則為止！
